# Aspiland code of conduct

Aspiland is an experimental, neurodiversity-aware project. Participation should support curiosity, autonomy, safety and understandable collaboration.

## Expected behaviour

Participants should:

- communicate honestly and distinguish fact, hypothesis, fiction, satire and personal experience;
- respect consent, privacy, personal boundaries and the right not to engage;
- criticize ideas and changes without degrading people;
- use clear criteria when evaluating work and explain consequential decisions;
- allow reasonable time for others to respond instead of creating unnecessary urgency;
- accommodate different communication styles, processing time and sensory needs where practical;
- minimize unnecessary personal data and never publish another person's sensitive information without authorization;
- correct mistakes openly and help make harmful or confusing processes safer.

## Unacceptable behaviour

The following is not acceptable in project spaces:

- harassment, threats, stalking, intimidation or deliberate humiliation;
- discrimination or degrading conduct based on identity, disability, health, neurotype, background or protected characteristics;
- unwanted sexual attention or sexualized content directed at another participant;
- doxxing, impersonation, credential sharing or exposing private communications without authorization;
- coercion, manipulative pressure, retaliation or punishment for declining participation;
- knowingly spreading materially false information that affects another person's safety, access or reputation;
- deliberately overwhelming others with noise, repetition, contact volume or other avoidable sensory or communication pressure;
- using administrative or technical access outside its documented purpose.

## Scope

This code applies to repository issues, pull requests, discussions, project communication and conduct carried out while representing Aspiland or using project access.

It does not regulate private life unrelated to the project. Local law and platform rules continue to apply.

## Reporting

Report conduct concerns privately to the repository owner or an identified maintainer. Do not place sensitive personal information, private messages or security material in a public issue.

A report should identify the relevant interaction, its impact and any immediate safety or access concern. Share only information necessary for a fair review.

## Response principles

Responses should be:

- prompt enough to reduce continuing harm;
- proportionate to the conduct and current risk;
- limited in scope and time where practical;
- explained to affected participants without exposing unnecessary private information;
- open to correction or review when new information appears.

Possible actions include clarification, requested correction, mediation, a communication boundary, temporary restriction, removal of specific access or exclusion from a defined project space. Irreversible or unrelated consequences are not appropriate.

## Good-faith disagreements

Disagreement, blunt technical criticism, declining a request or challenging governance is not misconduct by itself. The focus is on behaviour, impact, consent, accuracy and fair process rather than enforced agreement or politeness rituals.

## Changes to this document

This code is an operational participation policy, not canonical constitutional law. Consequential changes should be proposed transparently and reviewed by affected maintainers and participants.
