# Governance status

Status: descriptive; non-canonical  
Last reviewed: 2026-07-12

## Accepted and effective

- RFC 0001 — repository structure;
- RFC 0002 — repository hygiene baseline;
- RFC 0003 — removal of obsolete coercive and persistence rules;
- RFC 0005 — bounded System Guardian role;
- the current canonical documents explicitly stored under `canon/` with accepted status and effective dates;
- the change-control protocol as the working procedure referenced by accepted repository structure.

## Proposed and not yet effective

- RFC 0004 — governance automation backlog;
- RFC 0006 — data lifecycle and privacy baseline;
- RFC 0007 — mixed-content licensing strategy.

A proposal's presence on `main` records and publishes it for review. It does not create authority, grant rights or activate the proposed procedure.

## Current authority boundary

The GitHub repository owner has platform and operational control. Canonical governance changes still require an explicit decision, effective date, review opportunity and rollback path under the change-control process.

The System Guardian role is active in a bounded operational scope: Observe, Propose, Maintain and narrow emergency Contain. It has no unilateral authority over canon, people, ownership, legal commitments, spending or its own permissions. Elevated administration remains task-specific and explicitly authorized.

## Launch implication

Aspiland has enough structure for continued public repository cleanup and an eventual Repository Preview. It does not yet have the accepted operational package needed to claim a fully launched governed community.
